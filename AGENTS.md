# AGENTS.md: Voice Router

Главный файл с инструкциями для AI-агентов (Codex, Claude Code и других) и для людей в команде.
**Источник правды — этот файл.** `CLAUDE.md` только подключает его. Если правила расходятся, прав `AGENTS.md`.

## Проект

**Voice Router** — голосовой бот для вымышленной страховой компании **Saqta Insurance** (HackAlem AI, трек Halyk Bank, кейс 2). Клиент говорит в микрофон на русском, казахском или вперемешку. LLM-слой выбирает один из 40 сценариев стартового кита. Исполнитель собирает параметры, читает данные и отвечает голосом. Панель трассировки показывает, почему выбран именно этот сценарий.

- Главная спека: [`docs/specs/voice-router-spec.md`](docs/specs/voice-router-spec.md). **README стартового кита и `scenarios.json` главнее спеки.**
- Хакатон: **5 часов**, **3 человека**, из них ~3 часа на разработку.
- Приоритет: **точность маршрутизации и воспроизводимость > любая фича.** Дальше: рабочее демо > скорость > чистота кода > покрытие тестами.
- Порядок работы: **ADR → спека → код → PR → merge**. Код без спеки не пишем.

## Инварианты (нарушать нельзя)

- Домен — страхование. Примеры, тексты и демо только страховые.
- «Сегодня» — константа `DATASET_TODAY = 2026-10-01`. `date.today()` в доменной логике запрещён.
- Роутим по **всем 40 сценариям** + `SYS_OUT_OF_SCOPE`, `SYS_UNCLEAR`, `SYS_GOODBYE`. Сужать каталог нельзя.
- Сценарий выбирает **LLM**. Запрещены intent-классификатор как решающий слой, хардкод «реплика → сценарий» и обучение на строках `dev_utterances.json`.
- `not_this_if` переносим в карточки **дословно**.
- В критическом пути ровно **два LLM-вызова**: роутер и формулировка ответа.
- Факты (выплата, документ, полис, платёж, KB) берём только из данных, с `source`/`source_id`. LLM выбирает маршрут и формулирует, фактов не придумывает.
- Необратимое действие выполняется только после явного подтверждения клиента. Подтверждение привязано к параметрам.
- Не обещаем выпуск полиса, возврат денег или одобрение выплаты: в таких случаях handoff оператору с контекстом.
- Файлы кита не редактируем. Ожидаемые ответы dev-набора читает только evaluator.
- Персональные данные во внешние API не уходят. SMS и оператор — моки.
- Ограничения (неподдержанные действия, качество казахского, отсутствие streaming) честно пишем в README.

## Документация: ADR и спеки

### ADR — `docs/adr/NNNN-kebab-title.md`

Пишем, когда принимаем решение, которое дорого поменять: стек, БД, структура сервисов, внешний провайдер, формат API. Коротко, максимум 20–30 строк. Новый ADR добавляем в таблицу выше.

```markdown
# NNNN. Заголовок решения

- Статус: proposed | accepted | superseded by NNNN
- Дата: YYYY-MM-DD
- Автор: <имя>

## Контекст
Какую проблему решаем, ограничения (время, команда, демо).

## Решение
Что выбрали. Одним абзацем или списком.

## Альтернативы
- Вариант X — почему нет (1 строка)

## Последствия
Что станет проще или сложнее, известные риски.
```

### Спека — `docs/specs/<feature>.md`

Главная спека — `voice-router-spec.md`. Для отдельной фичи, которой там не хватает деталей, пишем короткую спеку **до кода** и ссылаемся на неё в PR.

```markdown
# Фича: <название>

- Владелец: <имя>
- Связанные ADR / разделы главной спеки: ...

## Цель

## Критерии приёмки

## Ключевые тесты
```

## Git и PR

- `main` всегда запускается. Прямые пуши в `main` запрещены, только PR.
- Ветки: `feat/<short>`, `fix/<short>`, `docs/<short>`, `infra/<short>`.
- Коммиты: Conventional Commits: `feat: ...`, `fix: ...`, `docs: ...`, `chore: ...`, `test: ...`.
- **Никаких упоминаний AI-ассистентов в коммитах и PR:** без `Co-Authored-By: Claude/Codex/...`, без «Generated with Claude Code» и похожих подписей. Автор коммита — человек из команды.
- PR маленькие, живут **не дольше ~45 минут**. Большую фичу режем на несколько PR.
- Перед PR: `git fetch && git rebase origin/main`, `just up` и `just test` проходят локально. Меняли роутер или карточки → `just eval` и цифры в описании PR.
- Merge: **squash**. Ревью: один человек, быстро (≤5 мин): смотрим контракт, работоспособность и секреты. Стиль не обсуждаем.

```bash
gh pr create --fill --base main
```

Шаблон описания PR:

```markdown
## Что
Кратко, что сделано.

## Спека / ADR
docs/specs/voice-router-spec.md, разд. N / docs/adr/NNNN-...

## Как проверить
just up && ...

## Eval (если трогали роутер)
primary accuracy: ru __ / kk __ / mixed __

## Чеклист
- [ ] just reset поднимает проект с нуля
- [ ] ключевые тесты проходят
- [ ] нет секретов в коде, новые env-переменные есть в .env.example
```

## Инфраструктура: docker compose

Проект целиком поднимается одной командой. Проверяющий запускает его **без нас**, только по README.

- `compose.yaml` в корне описывает **все** сервисы: `db` (Postgres), `backend` (FastAPI), `frontend` (Next.js).
- `.env.example` содержит все переменные с безопасными дефолтами. `.env` в `.gitignore`. Ключи провайдеров только через env.
- Без ключей проект обязан подниматься в мок-режиме (`MOCK_MODE`, ADR 0008) и выдавать понятную ошибку, а не 401.
- У сервисов есть `healthcheck`, а зависимости указаны через `depends_on: condition: service_healthy`.
- Миграции применяются автоматически при старте backend.
- Никаких ручных шагов вне `just up`. Если шаг нужен, он автоматизирован.

### justfile — единая точка входа

`just up`, `just down`, `just reset` (снести с данными и поднять), `just nuke` (снести всё, включая образы), `just build`, `just ps`, `just logs [service]`, `just test`, `just lint`, `just eval` (dev-оценка роутера, ADR 0007), `just migrate`, `just migration "msg"`, `just psql`, `just sh [service]`. Полный список: `just`.

Агенты запускают проект и тесты **только через `just`**, а не придумывают свои команды.

## Тесты: только ключевые

`just test` не ходит в LLM и внешние API и проходит быстрее ~1 минуты. Качество роутера меряет `just eval`, а не юнит-тесты.

**Пишем:**
- валидация ответа роутера: неизвестный ID сценария даёт ошибку
- пороги уверенности: маршрут, переспрос, handoff; `urgent` идёт первым
- подтверждение: смена параметров или отмена инвалидирует его, после подтверждения ровно одна запись
- применение `context_patch`: чужой `generation`/`client_id` или устаревшая версия отклоняются
- smoke: `/health` отвечает 200

**Не пишем:**
- тесты на геттеры, CRUD-обёртки, конфиги, UI-вёрстку
- тесты с точными строками из `dev_utterances.json`
- моки всего подряд ради покрытия, snapshot-тесты

## Конвенции кода

- Стек (ADR 0001): backend — Python 3.13, FastAPI, Pydantic v2, SQLAlchemy async, Alembic, uv; frontend — Next.js App Router, TypeScript; БД — PostgreSQL. Новые языки, фреймворки или сервисы добавляем только через ADR.
- Структура репо:
  ```
  compose.yaml, justfile, .env.example, README.md
  datasets/            # стартовый кит без изменений (ADR 0002)
  docs/adr/            # решения
  docs/specs/          # спеки
  backend/app/         # FastAPI: router/, executor/, background/, speech/, knowledge/, schemas/
  backend/migrations/  # alembic
  backend/tests/
  eval/                # генерация predictions для just eval
  frontend/src/app/    # экран звонка, панель трассировки, экран устройства слоя
  ```
- Frontend ходит в backend только через `/api/*` (Next rewrites → backend). URL бэкенда во фронте не хардкодим.
- Все контракты между слоями описаны Pydantic-моделями (`backend/app/schemas/`). Фронт повторяет их типами TS.
- Данные кита kernel получает **только** через `from app.knowledge import Knowledge` (каталог, клиенты, KB, поиск; см. `docs/specs/knowledge-module.md`). JSON-файлы и таблицу `kit_records` напрямую не читаем.
- Модели БД наследуются от `app.db.Base`. Их импорт добавляется в `backend/migrations/env.py`, после этого `just migration "..."`.
- Каждый этап (STT, роутер, чтения, ответ, TTS) пишет тайминг на доску. Замеры честные: параллельные ветки не складываем.
- Ошибки провайдера не роняют звонок: показываем понятное состояние в UI и пишем событие на доску.
- Линтер и форматтер: ruff и eslint, запускаются через `just lint`. О стиле не спорим.
- Hardcode и TODO допустимы, если помечены `# TODO(hack):` / `// TODO(hack):`.

## Правила для AI-агентов

1. Прочитай `AGENTS.md`, нужные разделы `docs/specs/voice-router-spec.md` и связанные ADR.
2. Нет нужной детали в спеке → допиши короткую спеку (и ADR, если решение архитектурное), закоммить, потом код.
3. Работай в отдельной ветке, никогда не коммить в `main` напрямую.
4. Держи изменения в своей зоне (таблица ролей). Не рефактори чужой код попутно.
5. Не нарушай инварианты выше. Если задача их требует, остановись и спроси.
6. Перед PR: `just reset` поднимает проект с нуля, `just test` зелёный, `just eval` — если трогал роутер или карточки.
7. Открой PR через `gh pr create` с описанием по шаблону. В коммитах и PR не добавляй подписи и co-author trailer'ы AI-ассистентов.
8. Меняешь контракт (схема, API, env) → обнови спеку/ADR и `.env.example` в том же PR.
9. Не уверен в продуктовом решении → выбери самое простое, что работает на данных кита (не только на демо-истории), и отметь это в PR.
10. Отвечай кратко, без длинных отчётов: время команды ограничено.
