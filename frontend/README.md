# Saqta Voice — клиент

Экран звонка, локальная история, серверный журнал трейсов и каталог сценариев из backend.
Дизайн и поведение: `../docs/specs/voice-router-frontend.md`; реализация:
`../docs/specs/voice-client-implementation.md`.

Каталог загружается из `/api/kit/scenario` и `/api/kit/system_intent`; локальная копия
и таблица названий удалены. Обновляется кнопкой и при возврате фокуса вкладки.
Счётчики, история и разбор используют полученные названия; пока сервер не отдаёт
переводы названий, они показываются в оригинале. Примеры вопросов доступны RU/KK.
Загрузка, ошибка с повтором, пустой каталог и отсутствие совпадений различаются.
Контракт: `../docs/specs/frontend-catalog-api.md`.

## Запуск и проверки

- В корне: `just up` — весь проект, `just test` — ключевые тесты backend.
- В `frontend/`: `just dev 3001` — отдельный Next dev server для наблюдения за изменениями.
- В `frontend/`: `just check`, `just lint`, `just test`, `just build`.
- Node 22.14+ для локального теста SSE; compose использует Node 24.

Браузер всегда обращается через `/api/*`. `BACKEND_URL` используется только сервером Next.
Если локальный порт 8000 занят другим приложением, задайте свободный `BACKEND_PORT`
в корневом `.env` и тот же адрес в `frontend/.env.local` через `BACKEND_URL`.
После изменения адреса перезапустите dev server. Например, текущий локальный просмотр:
backend 8010, Next 3001. Compose связывает сервисы по внутреннему адресу и не зависит от этого внешнего порта.

## Демо

1. Открыть `/`. Кнопки примеров вопросов заполняют черновик, без отправки и выбора маршрута.
2. «Посмотреть пример» открывает явно обозначенную демонстрацию UI на данных кита.
3. Для живого API отправить текст или записать и отправить аудио. Статус провайдеров приходит из `/capabilities`.
4. Выбрать реплику: видны маршруты, причины, факты, действия, ошибки и реальные замеры.
5. «Завершить звонок» сохраняет запись в истории вкладки. Перезагрузка очищает эту локальную историю.
6. В истории можно добавить 28 демонстрационных записей. Реальные API-сессии сохраняются отдельно от этих образцов по признаку режима.
7. Во время API-звонка вкладка «Трейс звонка» обновляет этапы по UUID сессии каждые 3 секунды, пока вкладка браузера видима. «Журнал трейсов» показывает серверные звонки с пагинацией 10/25/50, открытием по UUID и деревом выбранной трассы. Токены и длительности берутся с сервера; 404 до сохранения этапов показывается как ожидание. Контракт: `../docs/specs/frontend-traces.md`.

## Границы интеграции

- Подключён контракт модуля `call`, сохранённый в main 26e277c: UUID, POST SSE, context/board,
  router/last, cancel и playback. Все HTTP-вызовы находятся в `src/lib/api.ts`.
- В mock-режиме нет настоящих STT/LLM/TTS. UI не подбирает сценарий по фразе и не имитирует голосовой ответ.
- Browser MediaRecorder: webm/ogg, запись до 60 секунд, preview и явная отправка, предел API 10 МБ.
- Аудиопредложения воспроизводятся по `seq`. Стоп/новый звонок прекращает поток и звук, поздние события игнорируются.
- Замер browser EOS начинается при остановке записи, включает ожидание перед отправкой и заканчивается фактическим `playing`. Без аудио замер не отправляется.
- Полное голосовое демо и сценарные подтверждения требуют рабочих провайдеров/исполнителя коллег. В текущих моках это не проверено.
- На проверенном main bd67d9b реестры штатного `/calls` всё ещё содержат только mock
  для STT/роутера/TTS. Один OPENAI_API_KEY не включает этот путь. Реальный ответ отдельного
  kernel подтверждает доступ к модели, но не готовность звонка. Backend этим PR не меняется.
- История хранится в памяти вкладки, не на сервере. Аудио не архивируется. TXT-экспорт маскирует телефон и 12-значный ИИН, включая вложенный разбор.
- Источник текущего контекста — сервер. После хода берётся снимок; во время паузы активной сессии контекст проверяется каждые 2 секунды для поздних фоновых фактов. Старые версии и чужие поколения не применяются.
- Поддержка действия показывается только по `supported_actions`; наличие карточки не означает работающего исполнения.

## Ветки команды

PR #6 интегрировал blackboard kernel в main 26e277c. Совместимый `/calls` API сохранён,
ядро подключено к формированию ответа и общему контексту. Его отдельные возможности
теперь доступны по `/kernel/capabilities`.

Клиент использует совместимый поток `/calls`; новые optional response_id/segment_id
не мешают разбору событий. Подтверждение доставки отдельных сегментов и история
heard/partial/unheard ещё не подключены: отправляется только замер начала звука.
Эти возможности требуют отдельного клиентского шага и проверки с реальным TTS.
Backend и общие контракты этим PR не меняются.
