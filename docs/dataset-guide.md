# Стартовый кит Voice Router

В [`datasets/`](../datasets/) лежат все 11 исходных файлов из `case_2/voice_router_dataset/`.
Они перенесены побайтно, без вложенного каталога `voice_router_dataset`.
Это данные и описания контрактов; готовых обработчиков действий или API в ките нет.

Решения проекта: [ADR 0002](adr/0002-starter-kit-as-data.md) и [ADR 0007](adr/0007-evaluation-gate.md).
Если наша документация расходится с китом, исправляем документацию, а не исходные файлы.

## Что находится в каталоге

- [`README.ru.md`](../datasets/README.ru.md) — русское описание домена, структуры файлов,
  политики маршрутизации, общения, трассировки и оценки.
- [`README.md`](../datasets/README.md) — английская версия документации кита.
- [`README.kz.md`](../datasets/README.kz.md) — казахская версия документации кита.
- [`scenarios.json`](../datasets/scenarios.json) — 40 бизнес-сценариев и 3 системных намерения.
  В сценариях заданы описание, `not_this_if`, приоритет, слоты, действия и подтверждения,
  правила передачи оператору, примеры и ориентиры ответов на русском и казахском.
- [`slots.json`](../datasets/slots.json) — 43 параметра: типы, форматы, допустимые значения
  и вопросы для сбора недостающих данных на двух языках.
- [`actions.json`](../datasets/actions.json) — 31 действие, его входы, выходы и ошибки,
  признак необратимости, правила обработки ошибок и 6 очередей передачи оператору.
- [`knowledge_base.json`](../datasets/knowledge_base.json) — факты о компании, продуктах,
  ценах, офисах, клиниках, покрытии, документах и правилах обслуживания.
- [`mock_backend.json`](../datasets/mock_backend.json) — 11 клиентов, 11 полисов,
  4 страховых обращения и 2 платежа для реализации мок-действий.
- [`dialogs_sample.json`](../datasets/dialogs_sample.json) — 10 размеченных диалогов:
  смена темы и языка, возврат к вопросу, уточнения, подтверждения и передача оператору.
- [`dev_utterances.json`](../datasets/dev_utterances.json) — 104 размеченные реплики
  для независимой оценки маршрутизации, включая несколько намерений и смешанную речь.
- [`evaluate.py`](../datasets/evaluate.py) — исходный скрипт сравнения готовых predictions
  с ожидаемыми сценариями; сам не вызывает LLM и не генерирует предсказания.

Упоминания файлов в исходных README относятся к соседним файлам внутри `datasets/`.
Например, их `scenarios.json` — это `datasets/scenarios.json` от корня репозитория.
Примеры команд в README кита подразумевают текущим каталогом сам каталог данных;
это справочные примеры организаторов, а не готовые команды запуска нашего приложения.

## Данные во время звонка

Для runtime нужны `scenarios.json`, `slots.json`, `actions.json`,
`knowledge_base.json` и `mock_backend.json`.
Каталоги задают допустимые маршруты и контракты; факты берутся из данных, а не из ответа LLM.
Выбор охватывает все 40 сценариев плюс `SYS_OUT_OF_SCOPE`, `SYS_UNCLEAR`, `SYS_GOODBYE`.
При подготовке карточек роутера сохраняем `not_this_if` дословно.

Compose монтирует `./datasets` в backend как `/datasets` только для чтения.
Поэтому внутри контейнера путь к каталогу — `/datasets/scenarios.json`.
Само наличие volume не реализует загрузчик, роутер или действия: это отдельный код backend.
Изменения от действий, например обновление контакта, хранятся в Postgres поверх кита.
Исходные fixtures остаются неизменными; демо-события не подменяют исходные факты.

Компания Saqta Insurance, клиенты, цены и правила синтетические.
Они не описывают реальные страховые продукты или законодательство.
Для доменной логики используется `DATASET_TODAY = 2026-10-01`.
«Вчера» означает 2026-09-30, «завтра» — 2026-10-02 независимо от даты компьютера.
Не используем `date.today()` для сроков полисов и нормализации относительных дат.
Факты передаём с `source`/`source_id`; необратимые действия требуют явного подтверждения.

## Примеры и оценка отдельно от runtime

`dialogs_sample.json` помогает понять поведение диалога и подготовить проверки.
Это примеры, а не записанный сценарий, который приложение воспроизводит вместо обработки ввода.
`dev_utterances.json` и `evaluate.py` относятся к оценке и не загружаются в контекст звонка.
Весь dev-набор: 52 реплики RU, 45 KK, 7 mixed; 84 single, 13 multi-intent,
4 out-of-scope и 3 unclear.

Генератор predictions передаёт роутеру входной текст, но не `expected` и не подсказку `type`.
Ожидаемые сценарии читает только evaluator. Не включаем их в промпт, поиск контекста
или хардкод сопоставлений; не обучаем решение на точных строках dev-набора.
Оценка выполняется на чистых исходных данных, без изменений текущей демо-сессии.

Predictions — JSON-объект вида `{"U001": ["SC01"], "U081": ["SC27", "SC04"]}`.
Ключ — ID реплики, значение — упорядоченный список выбранных сценариев.
Исходный evaluator принимает файл predictions и путь к `dev_utterances.json`.
Отсутствующее предсказание считается ошибкой.

- `primary_accuracy` — первый предсказанный сценарий совпал с первым ожидаемым.
- `full_match` — множества сценариев совпали; порядок внутри множества не проверяется.
- `intent_recall` — доля найденных ожидаемых намерений только для multi-intent реплик.

Accuracy и full match выводятся для всего набора, каждого языка и типа запроса.
Multi-intent recall выводится общей метрикой для multi-intent части.
Скрипт не проверяет голос, слоты, факты, подтверждения, возврат к теме или задержку.
Эти свойства требуют отдельных проверок приложения.

ADR 0007 предусматривает `just eval`, который генерирует predictions реальной моделью
и вызывает исходный evaluator. **В текущем `justfile` такого рецепта пока нет.**
Импорт кита не добавляет eval pipeline и не подтверждает качество роутера.
Команды запуска и проверок проекта остаются в `just`; оценку подключаем отдельным рецептом.
