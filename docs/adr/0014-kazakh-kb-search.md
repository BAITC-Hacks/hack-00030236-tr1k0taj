# 0014. Казахский поиск по KB: ru/kk-расширения и несколько векторов на запись

- Статус: accepted
- Дата: 2026-09-23
- Автор: ye
- Основа: RAG из ADR 0011 (`knowledge_vectors`, `rag_query`, RRF)

## Контекст
KB в ките на английском, клиенты говорят на ru/kk/вперемешку. Вектор «запрос против английского документа» на казахском почти не находил нужную тему.

## Решение
- `just expand-kb` (офлайн, `gpt-5.5`): для каждой записи KB/справочника 6 ru + 6 kk + 3 mixed вопроса и описания ru/kk → `backend/app/knowledge/expansions.json` (в git). Привязка к хэшу payload; вопросы, дословно совпадающие с `dev_utterances.json`, отбрасываются.
- Тексты расширений добавляются в `search_text` — казахский ищется лексически даже без ключа; изменение `search_text` инвалидирует векторы (триггер из 0011).
- `knowledge_vectors.idx`: исходный текст + вопросы; сходство записи — лучший вариант; покрытие индекса считается по записям.
- `search_query` (английский перевод от роутера/kernel) эмбеддится вместе с текстом клиента: `0.3·sim(raw) + 0.7·sim(en)`. Вес лексики в RRF 0.3.
- Факты по-прежнему из кита; эмбеддятся только публичные документы.

## Последствия
`just eval-search` (47 запросов, recall@1 / @3), путь `rag_query`:

| режим | ru | kk | mixed |
|---|---|---|---|
| без ключа (лексика) | 0.83 / 1.00 | 0.84 / 0.96 | 0.60 / 1.00 |
| hybrid | 1.00 / 1.00 | 0.64 / 1.00 | 0.90 / 1.00 |
| hybrid + search_query | 1.00 / 1.00 | 0.96 / 1.00 | 1.00 / 1.00 |

До изменений (RRF, без расширений, kk) топ-3 ≈ 0.27. Набор запросов написан вручную — казахские формулировки и сгенерированные вопросы нужно проверить носителю.
