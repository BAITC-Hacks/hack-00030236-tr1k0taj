# 0008. Голос, провайдеры и режим без ключей

- Статус: proposed — провайдеры подтверждаем проверкой доступов в первые 15 минут
- Дата: 2026-09-23
- Автор: ye
- Спека: docs/specs/voice-router-spec.md (разд. 8, 10, 13.2)

## Контекст
Нужны голос ru/kk/mixed в вебе, честный замер задержек и запуск проверяющим без наших аккаунтов.

## Решение
- **Push-to-talk**: браузер записывает реплику, отправляет на backend, backend вызывает готовый STT API, отвечает текстом и аудио TTS. Streaming не делаем и в README не заявляем.
- Провайдеры STT/TTS/LLM — за адаптерами в backend, выбор через env. Кандидат для речи — Azure Speech (RU/KZ, казахские голоса), если доступ уже есть. Новое облако не регистрируем. Казахский голос браузера не используем без проверки.
- Проверка в первые 15 минут: чистый ru, чистый kk, смешанная фраза, казахская озвучка.
- Текстовый ввод — резервный канал.
- **Режим без ключей**: `MOCK_MODE` для речи и LLM с понятной ошибкой при отсутствии ключей, чтобы проверяющий не упёрся в 401. Мок не заменяет живой LLM-путь на демо.
- Ключи только через env, в `.env.example` — плейсхолдеры.
- Замеры раздельно: STT, роутер, чтения, генерация ответа, первый аудиоблок, end-of-speech → начало воспроизведения в браузере. Параллельные ветки не складываем, фразу-заполнитель за ответ не выдаём.
- `getUserMedia`: localhost или HTTPS, проверить на стенде до репетиции.

## Открытые вопросы
Демонстрационный ключ от организаторов; конкретные провайдер и модель LLM; HTTPS на стенде.
