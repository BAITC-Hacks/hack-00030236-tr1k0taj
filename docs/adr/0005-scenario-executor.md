# 0005. Исполнитель сценариев как автомат над данными

- Статус: accepted
- Дата: 2026-09-23
- Автор: ye
- Спека: docs/specs/voice-router-spec.md (разд. 6)

## Контекст
40 сценариев за 3 часа нельзя написать кодом по одному. Нужны подтверждения необратимых действий и обязательный handoff.

## Решение
- Один исполнитель на все сценарии, параметризованный карточкой из кита. Это обычный код, LLM в нём только формулирует ответ (второй и последний LLM-вызов критического пути).
- Автомат: слоты не полны → вопрос по недостающему; полны → чтения → ответ; необратимое действие → preview → явное подтверждение → выполнение; не поддержано → честно сказать и handoff.
- Поддерживаемые действия: `find_client`, `get_claim`, `kb_lookup`, `get_offices`, `check_payment`, `transfer_to_operator`, `update_contact`. Остальные из `actions.json` помечены как неподдержанные и ведут к оператору. **Это ограничение пишем в README.**
- `pending_confirmation` привязан к действию **и параметрам**. Изменение параметров или отмена инвалидирует подтверждение.
- Слоты: уже известное по клиенту повторно не спрашиваем; новое значение из реплики сильнее старого.
- Отложенные темы — стек `pending_topics` с возвратом к прерванной теме.
- Не обещаем того, что сценарий не разрешает: выпуск полиса, возврат денег, одобрение выплаты.
- SMS и оператор — моки с видимым результатом.

## Последствия
- 41-й сценарий добавляется правкой JSON.
- Покрытие действий неполное, и мы это открыто показываем.
