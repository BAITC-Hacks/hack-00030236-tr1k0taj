# 0012. Слои модулей backend и автоматическая проверка импортов

- Статус: accepted
- Дата: 2026-09-23
- Автор: ye

## Контекст
ADR 0009 ввёл модули с публичным API, но направление зависимостей никто не проверяет. Модули пишут
параллельно, и циклы или импорты внутренних файлов соседа появляются незаметно.

## Решение
- Модули `backend/app/*` разложены по слоям (сверху вниз). Импорт идёт только вниз, пропускать слои можно:
  1. composition root: `main`;
  2. api: `call`, `docs` (разрешено `call → docs`: это текст OpenAPI);
  3. speech: `speech` (STT/TTS, предобработка), не импортирует agent;
  4. agent: `kernel`, `router`, `executor`, соседи могут импортировать друг друга; не импортирует speech;
  5. data: `context`, `knowledge`, друг от друга независимы;
  6. infra: `tracer` (сквозной), `config`, `db` (разрешено `db → config`).
- Соседи по слою независимы, если связь не перечислена выше.
- Чужой модуль импортируем только через `from app.<module> import ...`, без `app.<module>.<sub>`.
  `app.config`, `app.db`, `app.docs` — простые модули-файлы.
- Проверка: `backend/tests/test_module_boundaries.py` (ast, stdlib) в `just test`, учитывает и ленивые импорты.
  Текущие нарушения — в `ALLOWED_EXCEPTIONS` с `# TODO(hack):`, убираются отдельными PR.

## Альтернативы
- import-linter — новая зависимость ради 60 строк теста.
- Договорённость без проверки — нарушения находим поздно.

## Последствия
- Новый модуль нужно добавить в ADR и в `LAYERS` теста, иначе тест падает.
- Нарушение видно в `just test`, а не на ревью.
