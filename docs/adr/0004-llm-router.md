# 0004. LLM-роутер сценариев

- Статус: accepted
- Дата: 2026-09-23
- Автор: ye
- Спека: docs/specs/voice-router-spec.md (разд. 4.1, 4.2, 5)

## Контекст
ТЗ требует, чтобы сценарий выбирал LLM-слой, а не готовый intent-классификатор. Точность маршрутизации — главный критерий.

## Решение
- **Один LLM-вызов** на реплику. Вход: текущая реплика, последние ходы, проверенный контекст, карточки **всех** 43 сценариев.
- Карточка сценария: id, назначение, маркеры выбора, `not_this_if` **дословно** из кита, приоритет, примеры ru/kk.
- Системная часть промпта (карточки, правила, пороги) неизменна и кэшируется (prompt caching). Переменная часть — диалог и контекст.
- Ответ — строгий JSON; `scenarios` первым полем: `scenarios, alternatives, language, slots, is_continuation, confidence, reason`.
- Pydantic-валидация: неизвестный ID сценария — ошибка, а не «похожий» сценарий.
- Пороги: ≥0.75 — маршрутизируем; 0.45–0.75 — один переспрос; <0.45 дважды или просьба клиента — оператор с контекстом. Сценарии `urgent` обслуживаются первыми.
- `reason` — проверяемые признаки и граница с соседним сценарием, не поток рассуждений.
- На роутинге — быстрая модель.
- Экран «устройство слоя»: реальный промпт роутера и последний сырой ответ модели.

## Запрещено
Классификатор как решающий слой; хардкод реплика→сценарий; обучение на строках dev-набора; retrieval-шортлист без пометки в README и логирования расхождений.

## Последствия
- Ошибки на стыке сценариев лечим карточками и `not_this_if`, а не сменой модели.
- `confidence` не откалиброван, пороги проверяем на dev-наборе (ADR 0007).
