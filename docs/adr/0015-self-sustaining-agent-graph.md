# 0015. Самоподдерживающийся граф фоновых агентов

- Статус: accepted
- Дата: 2026-09-23
- Автор: зона A
- Спека: [kernel-graph-loop.md](../specs/kernel-graph-loop.md)
- Связанные: ADR 0011 (ядро), ADR 0014 (blackboard v2)

## Контекст
Сейчас фон — одноразовая волна на ход: триггеры только `user.message` и `agent.result`,
агент стартует раз на `input_revision`, конец ответа завершает работу. Фон стартует
одновременно с речью и обязан уложиться в генерацию первого сегмента (0,6–1,5 с),
поэтому в текущий ответ почти никогда не попадает, а между ходами не работает ничего.

## Решение
- Добавляем триггеры `response.completed` и `record.changed`: граф продолжает работу
  в паузе между ходами и перезапускает агента при изменении его `reads`.
- Актуальность запуска — fingerprint входов агента (ADR 0014), а не равенство ревизий.
- Затухание гарантируют квиесценция (крутимся, пока меняются входы) и бюджеты
  `max_runs_per_turn` / `max_runs_per_session`.
- Поздний результат оседает записью на доске и никогда не инициирует речь.
- Для первого хода, где графа ещё нет: режим агента `reader` без вызова модели и
  флаг `blocking` с дедлайном перед первым сегментом (спека Voice Router, разд. 7.1/7.3).

## Альтернативы
- Оставить одноразовую волну и компенсировать таймаутами — фон продолжает не успевать.
- Отдельный планировщик-LLM — лишний вызов на критическом пути, запрещён ADR 0011.

## Последствия
Фоновая работа переносится в тишину между ходами, к следующему вопросу факты уже на доске.
Появляется риск бесконечной работы: его закрывают бюджеты и квиесценция, обе величины
наблюдаемы событием `graph.budget_exhausted`. Один worker остаётся ограничением v1.
