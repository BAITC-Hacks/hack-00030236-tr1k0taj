# 0003. Доска (blackboard) как рабочая память диалога

- Статус: accepted
- Дата: 2026-09-23
- Автор: ye
- Спека: docs/specs/voice-router-spec.md (разд. 3, 4.3, 4.4, 4.6)

## Контекст
Роутеру, исполнителю, фоновому помощнику и панели трассировки нужна общая, объяснимая картина диалога.

## Решение
- Общая память диалога — append-only доска из `BoardEntry` (`turn_id`, `type`, `author`, `payload`, `source`, `source_id`, `confidence`, `ts_start_ms/ts_end_ms`, `context_version`).
- Состояние сессии — `SessionContext` (`generation`, `context_version`, `client_id`, `active_scenario`, `pending_topics`, `slots_by_topic`, `pending_confirmation`, `facts`).
- Хранение: две таблицы Postgres с JSONB — `sessions` и `board_entries`. Очередь задач не нужна.
- Один процесс backend. Перезапуск завершает активный звонок.
- `context_version` растёт только при значимых изменениях контекста. Trace, тайминги и события воспроизведения версию **не** меняют.
- Панель трассировки — это рендер доски без преобразований, а не отдельный лог.
- Каждый факт несёт `source` и `source_id`.

## Альтернативы
- Redis или очередь — лишний сервис, для одного процесса не нужен.
- Отдельный лог трассировки — расходится с реальным состоянием.

## Последствия
- Трассировка бесплатна и честна: показывает то, что видел роутер.
- Смена клиента или «новый звонок» повышает `generation`, история не протекает между звонками.
