# Фича: клиент Voice Router

- Владелец: B — frontend
- Связанные ADR: 0001, 0003–0006, 0008; главная спека, разделы 8–10.
- Детальный дизайн: [voice-router-frontend.md](voice-router-frontend.md).

## Цель

Жюри при первом открытии понимает назначение приложения, записывает вопрос и видит ответ, выбранный сценарий и источники. Реализуем клиент в существующем Next.js с зелёным акцентом по референсу Halyk.

## Пользовательский сценарий

1. Пользователь открывает экран звонка, видит инструкцию и начинает запись или текстовый ввод.
2. Клиент записывает аудио браузерным MediaRecorder, позволяет прослушать/удалить запись и отправляет её через согласованный адаптер.
3. Транскрипт, контекст и разбор показывают полученные данные. Отмена и новая сессия защищены от позднего ответа.
4. История текущей вкладки и полный каталог сценариев доступны без потери активного разговора.

## Контракт

На исходном коммите 2a137a4 реализован только GET /api/health → {status, db}. API звонков, аудио и событий ещё не опубликован. UI-адаптер отделяет представление от транспорта. Не придумываем HTTP endpoints и не реализуем роутер на клиенте. До подключения показываем недоступность интеграции; локальные образцы явно помечаем демонстрацией интерфейса. Проверка MediaRecorder не считается работающим STT/TTS.

Используем описанные в главной спеке BoardEntry/SessionContext как ориентир; окончательные TS-типы должны соответствовать опубликованным моделям коллег. Сохраняем прокси /api/*.

## Критерии приёмки

- [ ] Понятный первый экран, responsive UI RU/KK, доступное управление клавиатурой, отсутствие авторизации.
- [ ] Запись/прослушивание/отмена аудио и явные ошибки браузера; позднее аудио не играет после отмены/новой сессии.
- [ ] Транскрипт, источник факта, разбор маршрута и raw-данные отображаются без придуманных решений/измерений.
- [ ] Каталог содержит 40+3 исходных сценария с поиском, фильтрами, пагинацией, дословными not_this_if.
- [ ] История хранит доступные сессии вкладки и честно показывает отсутствие записей/совпадений.
- [ ] Согласованный API подключается по его реальному контракту при появлении в общем репозитории.

## Вне скоупа

Backend, LLM/STT/TTS-провайдеры, серверное хранение истории, авторизация, редактирование каталога, full duplex/barge-in. Работоспособность живого голосового тракта требует API коллег.

## Ключевые проверки

Ручная проверка записи и ошибок микрофона, клавиатуры/адаптивности, составных фильтров и пагинации. Проверка отменённого хода/новой сессии с запоздавшим результатом при наличии адаптера. Запуск и проверки проекта через just.
