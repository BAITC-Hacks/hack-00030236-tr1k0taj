# Фича: клиент Voice Router

- Владелец: B — frontend
- Связанные ADR: 0001, 0003–0006, 0008; главная спека, разделы 8–10.
- Детальный дизайн: [voice-router-frontend.md](voice-router-frontend.md).

## Цель

Жюри при первом открытии понимает назначение приложения, записывает вопрос и видит ответ, выбранный сценарий и источники. Реализуем клиент в существующем Next.js с зелёным акцентом по референсу Halyk.

## Пользовательский сценарий

1. Пользователь открывает экран звонка, видит инструкцию и начинает запись или текстовый ввод.
2. Клиент записывает аудио браузерным MediaRecorder, позволяет прослушать/удалить запись и отправляет её через согласованный адаптер.
3. Транскрипт, контекст и разбор показывают полученные данные. Отмена и новая сессия защищены от позднего ответа.
4. История текущей вкладки и полный каталог сценариев доступны без потери активного разговора.

## Контракт

Опубликованный контракт — `docs/specs/call-api.md`, сохранённый в main 26e277c. Клиент генерирует UUID и создаёт звонок через POST /api/calls. Отправляет текст в /calls/{id}/turns/text, аудио multipart в /calls/{id}/turns/audio; читает SSE через fetch. Типы повторяют используемые HTTP-ответы модулей call/context. GET /api/capabilities определяет реальный режим провайдеров. Ошибки моков показываются явно, без придуманного маршрута.

События transcript, routing, facts, action, reply.delta/reply.done обновляют интерфейс по мере получения. turn.done завершает обработку; audio воспроизводится последовательно, только для текущего запроса. Отмена обрывает fetch, останавливает звук и вызывает /calls/{id}/turns/{turn_id}/cancel. Поздние события из прежней сессии игнорируются. /router/last кешируется только для совпавшего turn_id; context/board дают источники и подтверждения. Тексты и промпты показываются как текст, без HTML.

Для замера голосового ответа сохраняем performance.now() при остановке записи и при фактическом событии playing. Время включает паузу на прослушивание записи до отправки; интерфейс явно объясняет это. Серверные latency_ms подписываются отдельно. Без начавшегося звука замер playback не отправляется. Язык UI не передаём как language_hint.

Завершение звонка архивирует его в памяти вкладки; серверного /calls/{id}/end нет. Новый звонок использует новый UUID, прекращает предыдущую обработку и сохраняет завершённый разговор в локальной истории. История не хранит аудио. Образцы интерфейса отделены от живых сессий; не заменяют реальные записи. PR #6 интегрировал kernel через совместимый call API. Optional response_id/segment_id не ломают транспорт; подтверждения доставки сегментов и их heard/partial/unheard-история остаются следующим клиентским шагом, отдельно от текущего EOS-замера.

При архивировании отменённый последний ход даёт результат interrupted; успешный последующий ход позволяет завершить разговор как completed, а уже выполненная передача оператору сохраняет результат handoff.

Используем описанные в главной спеке BoardEntry/SessionContext как ориентир; окончательные TS-типы должны соответствовать опубликованным моделям коллег. Сохраняем прокси /api/*.

## Критерии приёмки

- [ ] Понятный первый экран, responsive UI RU/KK, доступное управление клавиатурой, отсутствие авторизации.
- [ ] Запись/прослушивание/отмена аудио и явные ошибки браузера; позднее аудио не играет после отмены/новой сессии.
- [ ] Транскрипт, источник факта, разбор маршрута и raw-данные отображаются без придуманных решений/измерений.
- [ ] Каталог содержит 40+3 исходных сценария с поиском, фильтрами, пагинацией, дословными not_this_if.
- [ ] История хранит доступные сессии вкладки и честно показывает отсутствие записей/совпадений.
- [ ] Согласованный API подключается по его реальному контракту при появлении в общем репозитории.

## Вне скоупа

Backend, LLM/STT/TTS-провайдеры, серверное хранение истории, авторизация, редактирование каталога, full duplex/barge-in. Работоспособность живого голосового тракта требует API коллег.

## Ключевые проверки

Ручная проверка записи и ошибок микрофона, клавиатуры/адаптивности, составных фильтров и пагинации. Проверка отменённого хода/новой сессии с запоздавшим результатом при наличии адаптера. Запуск и проверки проекта через just.

Для потокового транспорта: один тест разбора фрагментированных SSE/UTF-8 и завершения потока; один тест последовательного применения событий с сохранением фактов. Это проверки нетривиальной логики демо, не UI-снимки.
