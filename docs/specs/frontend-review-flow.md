# Фича: понятный просмотр серверного звонка

- Владелец: B — frontend
- Основа: voice-router-frontend.md, frontend-traces.md, существующий HTTP/SSE-контракт.

## Цель
Жюри должно за один проход увидеть вопрос, состояние обработки, результат и его объяснение. Технические детали доступны по раскрытию и не вытесняют смысл ответа.

## Поведение
- Все звонки, ответы, маршруты и факты приходят из backend. Локальные демонстрационные диалоги, записи истории, кнопки заполнения тестовых данных и режим example удаляются по поручению владельца.
- История и трейсы объединены в «Историю звонков» на /history: источник GET /api/traces/sessions, детали по UUID и дерево трассы. Старый /traces перенаправляет на /history с сохранением session/trace.
- Каталог и его примеры вопросов сохраняются только как данные GET /api/kit; локального выбора маршрута и fallback-данных нет.
- Отправленный текст очищается из редактора после принятия сервером; при ошибке транспорта черновик сохраняется для повтора.
- Во время обработки показано понятное текущее состояние. В трейс передаётся ID последнего отправленного хода, включая ещё не завершённый.
- В трейсе сначала видны реплика, выбранный маршрут либо объяснение сбоя; UUID, модели, события и дерево доступны ниже. Длительности длиннее секунды отображаются в секундах/минутах, точные значения сохраняются в исходных данных.
- Читаемые названия этапов дополняют исходные технические имена. Служебные трассы остаются доступны, но не мешают выбору ходов.
- Поиск UUID не зависит от регистра. Журнал сохраняет честную серверную пагинацию и понятные состояния загрузки/ошибки/пустого результата.

## Приёмка и проверки
- [ ] В браузере отсутствуют демонстрационные диалоги и генерация истории.
- [ ] Пройден живой запрос → трейс того же UUID → журнал → возврат.
- [ ] Один пункт «История звонков» показывает серверные данные; после перезагрузки история доступна.
- [ ] Ошибка сервера объяснена человеку, её исходные сведения можно раскрыть.
- [ ] Frontend just check/lint/test/build проходят.

## Вне скоупа
Backend, провайдеры, авторизация, симуляция успешного живого роутинга и новые API.
