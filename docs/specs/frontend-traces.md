# Фича: серверные трейсы в клиенте

- Владелец: B — frontend
- ADR: 0001, 0013; контракты call-api.md и tracer-module.md, main 68f9999.

## Цель и сценарий
Жюри открывает серверную трассировку выбранной реплики и видит реальные этапы, длительности, модель, токены и ошибки. Раздел «Трейсы» показывает сохранённые на сервере звонки независимо от локальной истории вкладки.

## Контракт
- GET /api/traces/sessions?limit&offset → SessionTraceSummary[], новые по последней активности первыми. Total отсутствует: запрашиваем pageSize+1 для честного Next, показываем диапазон без выдуманного общего количества.
- GET /api/traces/sessions/{session_id} → SessionTrace (summary, turns, traces).
- GET /api/traces/{trace_id} → TraceView с деревом spans/children, events, links и attributes.
- Даты ISO UTC, duration_ms уже в миллисекундах. Параллельные этапы не складываем в итог.
- Сохраняем traceparent/x-trace-id из HTTP-ответа SSE на конкретной реплике; turn.done.trace_id дополняет ID. cancel и playback передают traceparent именно этой реплики, без переноса между звонками.
- Переход из разбора: /traces?session=<UUID>&trace=<trace_id>. Незавершённый или ещё не сохранённый трейс может дать 404: показываем ожидание с обновлением, не ошибку разговора.

## Критерии приёмки
- [ ] Раздел с реальной серверной историей, пагинацией 10/25/50 и ручным обновлением; никаких демонстрационных трасс.
- [ ] Детали звонка и дерево выбранной трассы, длительности/ошибки/токены, исходные атрибуты в раскрывающемся блоке.
- [ ] Ссылки из текущего звонка и истории, без потери текущего разговора.
- [ ] Отдельные состояния загрузки, пустого списка, 404 и сетевой ошибки; поздние ответы не подменяют выбранную запись.
- [ ] Остановка и playback попадают в исходную трассу через полученный traceparent.

## Проверки
Frontend just check/lint/test/build. Один транспортный тест корреляции SSE headers → cancel/playback и сохранения trace_id при финальном событии; ручная проверка живого mock-вызова, его server trace и списка. Backend не меняем.

## Вне скоупа
Редактирование backend/контрактов, новые провайдеры, поиск/фильтры которых сервер не поддерживает, имитация успешной обработки, замена локальной истории или сегментные playback acknowledgements.
