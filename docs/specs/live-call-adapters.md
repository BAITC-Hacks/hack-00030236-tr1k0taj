# Фича: минимальный живой звонок OpenAI

- Владелец: интеграция демо по поручению Aidar
- ADR: 0004, 0008, 0012, 0014; docs/specs/call-api.md.

## Цель и сценарий
Браузер записывает вопрос, отправляет multipart в существующий /calls/{id}/turns/audio, получает транскрипт, маршрут и ответ с аудио. Stop прерывает поток и звук. Текстовый ввод работает по тому же роутеру.

## Контракт
- STT_PROVIDER=openai: SpeechToText.transcribe принимает webm/ogg/wav и возвращает Transcript через серверный OpenAI Audio API.
- LLM_PROVIDER=openai: ScenarioRouter.route делает один Responses API вызов по полному каталогу из Knowledge, исходным not_this_if и разрешённому router view; возвращает RouterResult/RouterOutput. Проверка ID и порогов остаётся текущей.
- TTS_PROVIDER=openai: TextToSpeech.synthesize возвращает AudioChunk MP3 из OpenAI Audio API. Текст и аудио идут через существующие SSE-события.
- OPENAI_API_KEY/LLM_MODEL уже существуют. Речевые модели и голос задаются STT_MODEL/TTS_MODEL/TTS_VOICE с документированными безопасными дефолтами. Ключ не передаётся клиенту, в промпте роутера личные идентификаторы маскируются.
- MOCK_MODE=true либо отсутствие ключа не инициирует платных запросов. Ошибки провайдера передаются как понятные ошибки этапа, без ключей/сырых HTTP-заголовков.

## Критерии приёмки
- [ ] Сохраняется запуск без ключа и прежний HTTP-контракт.
- [ ] Один живой вопрос из браузера проходит STT → маршрутизация → текст/аудио; ошибки и Stop остаются управляемыми.
- [ ] Полный каталог используется без локального классификатора или хардкода фраз.
- [ ] Дефолты env описаны, реальный ключ только в игнорируемом .env.

## Проверки
Один тест адаптеров речи с подменённым HTTP-транспортом и один тест роутера на полный каталог/валидацию ответа, без внешних вызовов. just test; ручной синтетический текстовый/аудио запрос к локальному backend и запись/отмена в браузере.

## Вне скоупа
Новые действия исполнителя, изменение kernel/HTTP/БД, обучение или eval на dev_utterances, гарантия качества казахского, full duplex.
