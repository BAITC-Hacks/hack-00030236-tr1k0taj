# Фича: каталог клиента из API

- Владелец: B — frontend
- ADR: 0001, 0002, 0009; контракт knowledge из main 9fe5f47.

## Цель

Изменения сценариев на сервере видны в каталоге, истории и разборе звонка без сборки frontend. Встроенный scenarios.json и отдельная таблица названий удаляются.

## Сценарий и контракт

1. Общий провайдер интерфейса загружает GET /api/kit/scenario и GET /api/kit/system_intent через существующий Next proxy. Backend возвращает полные массивы, без серверной пагинации.
2. Поиск, составные фильтры, сортировка и пагинация работают с полученным массивом. Счётчики отражают фактическое количество записей.
3. Названия берём из name, системные исходы — из description. Backend пока не содержит перевода названий RU/KK: показываем оригинал, примеры/ответы берём по языку интерфейса. not_this_if сохраняем дословно.
4. Загрузка, ошибка с повтором, пустой серверный каталог и отсутствие совпадений различаются. Локального запасного каталога нет; неизвестный маршрут в истории/разборе показывается своим ID.
5. Обновление каталога доступно кнопкой и при возврате фокуса вкладки. Устаревший запрос не заменяет более новый. Обновление не прерывает звонок.

## Критерии приёмки

- [ ] Во frontend нет копии scenarios.json и таблицы SCxx → название.
- [ ] Каталог, названия в истории и разборе используют один полученный каталог.
- [ ] Есть загрузка, повтор после ошибки, пустой результат и работоспособная пагинация/переход к соседней карточке.
- [ ] Изменённые на backend названия и количество видны после обновления без пересборки.

## Проверки

Frontend just check/lint/test/build; браузерная проверка списка, системных исходов, фильтра, карточки и повторной загрузки. Один тест транспорта на получение обеих коллекций и ошибку API, без UI snapshot.

## Вне скоупа

Изменения API, редактирование карточек, перевод доменных данных на клиенте, серверная пагинация.
